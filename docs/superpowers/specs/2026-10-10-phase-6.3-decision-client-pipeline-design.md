# Phase 6.3 Design — `IDecisionClient abstraction and pipeline`

**Date:** 2026-10-10
**Phase:** `6.3`
**Surface:** `Backend`
**Stage:** phase (one phase, implementation-ready)

## Goal

`IDecisionClient` becomes one provider-neutral call: a `DecisionRequest` in, a `DecisionResponse` or a `DecisionError` out. Retries, logging and telemetry become public, composable stages around a transport, and anyone can add a stage of their own (#119). The parts Phase 6.2 left outside the protocol seam move behind it, so nothing but `Protocols/` knows the `/v1/systemone` shape, apart from the two raw System One calls that 6.4 moves out.

## Decisions (maintainer, 2026-10-10)

- **Where it lives:** `IDecisionClient` and the pipeline live in the core `Minos.NET` package, with no `Microsoft.Extensions.AI` dependency. A later `Minos.NET.Extensions.AI` package bridges to `IChatClient`.
- **The core call:** `EvaluateAsync(DecisionRequest, CancellationToken)` returns `Result<DecisionResponse, DecisionError>`. The response carries neutral per-question answers. The typed `EvaluateAsync<T>` and the `QuestionSet` overloads become extension methods that build their answers with `T.Create`.
- **The raw System One API:** `EvaluateAsync(SystemOneRequest)` and `ListModelsAsync` leave the interface. They stay public on the concrete `DecisionClient`, reachable through `GetService<DecisionClient>()`, until 6.4 moves them into `Minos.NET.SystemOne`.
- **Defaults:** `new DecisionClient(...)` and `AddDecisionClient` still build the standard pipeline: telemetry, logging when a logger factory is given, and retries. One option, `UseStandardPipeline = false`, gives the bare transport.
- **Scope:** the extension point, meaning the builder and the delegating base, plus the three standard stages. Fallback and escalation stay in Milestone 10. Caching and rate-limiting stages are tracked in #143 for a later phase.
- **Approach A: every stage is an `IDecisionClient`.** The stages use only `DecisionRequest`, `DecisionResponse` and `DecisionError`, so one pipeline definition works unchanged over the 6.4 and 6.5 adapters. Two alternatives were rejected:
  - Wrapping the whole client in a public builder while the standard stages keep their internal wiring leaves retries as an HTTP detail every adapter rebuilds, and misses the phase goal.
  - Making telemetry and logging stages but leaving retries in the HTTP layer, as M.E.AI advises, means retries cannot see `DecisionError` kinds, and the default would differ between protocols.
- **Pretty builder:** every stage has a `Use…` extension on `DecisionClientBuilder`, and `AsBuilder()` starts a builder from any client, following M.E.AI's pattern.

## The neutral call

```csharp
public interface IDecisionClient : IDisposable
{
    ValueTask<Result<DecisionResponse, DecisionError>> EvaluateAsync(DecisionRequest request, CancellationToken cancellationToken = default);
    object? GetService(Type serviceType, object? serviceKey = null);
}
```

| Type | Shape |
|---|---|
| `DecisionRequest`, sealed class | `Definition`: a `QuestionSetDefinition`<br>`State`: a `DecisionContent`<br>`Model`: a nullable string; null means the transport's `DecisionClientOptions.Model`<br>`RetryAttempt`: an int, 0 on the first attempt. The retry stage sends `request with { RetryAttempt = n }`, the only allocation a retry adds, so the transport can send `X-TypeSafe-Retry-Count`. |
| `DecisionResponse`, sealed class | `Model`, `Usage` (the existing `DecisionUsage`), `Id`, `Provider` (both nullable)<br>`Answers`: a `QuestionAnswerList` in `Definition` order<br>Internally, the `AnswerSlot[]` and probabilities the protocol read, so `T.Create` builds typed answers without parsing again. A public constructor takes the definition, `QuestionAnswer`s, model and usage, and fills the slots, so a test fake can return a response that `T.Create` reads. |
| `QuestionAnswerList`, readonly struct | `Count`, an indexer and a struct enumerator: a view over the slots that allocates nothing. It does not implement `IReadOnlyList<QuestionAnswer>`, because boxing it would hide an allocation. |
| `QuestionAnswer`, readonly struct | `Key`, `Kind`<br>`Value`: the Noul value or the score<br>`ChosenIndex`: the option or level position, -1 for Noul<br>`Confidence`<br>`Probabilities`: a `ReadOnlySpan<double>`, one per option or level |
| `DecisionClientMetadata`, sealed record | `ProviderName`, `Endpoint` (a nullable `Uri`), `DefaultModel`. Returned by `GetService`; the telemetry stage reads it. |

- **Extension methods:** the typed `EvaluateAsync<T>` (state as string, `JsonElement`, typed state with `JsonTypeInfo`), `EvaluateUtf8Async<T>` and the `QuestionSet` overloads move to `DecisionClientExtensions`. Each one builds a `DecisionRequest` from `T.Definition` or `QuestionSet.Definition`, calls the core method, and maps the response with `T.Create` or `Answers`. They work on any `IDecisionClient`. The interface's default methods go away. `GetService<T>(this IDecisionClient, object? serviceKey = null)` is a typed lookup.
- **Breaking:** the interface's members, the typed members becoming extensions, and `IDisposable` on the interface. That is acceptable in 0.x and ships under a `feat!` commit.

## The pipeline

### Delegating base and builder

```csharp
public abstract class DelegatingDecisionClient : IDecisionClient
{
    protected DelegatingDecisionClient(IDecisionClient innerClient);
    protected IDecisionClient InnerClient { get; }
    public virtual ValueTask<Result<DecisionResponse, DecisionError>> EvaluateAsync(DecisionRequest request, CancellationToken cancellationToken = default);
    public virtual object? GetService(Type serviceType, object? serviceKey = null);   // this when the type matches and the key is null; else the inner client
    public void Dispose();                                                            // Dispose(true) and SuppressFinalize
    protected virtual void Dispose(bool disposing);                                   // disposes the inner client
}

public class DecisionClientBuilder
{
    public DecisionClientBuilder(IDecisionClient innerClient);
    public DecisionClientBuilder(Func<IServiceProvider, IDecisionClient> innerClientFactory);
    public DecisionClientBuilder Use(Func<IDecisionClient, IDecisionClient> stageFactory);
    public DecisionClientBuilder Use(Func<IDecisionClient, IServiceProvider, IDecisionClient> stageFactory);
    public DecisionClientBuilder Use(Func<DecisionRequest, IDecisionClient, CancellationToken, ValueTask<Result<DecisionResponse, DecisionError>>> evaluate);
    public IDecisionClient Build(IServiceProvider? services = null);   // null: an empty provider
}
```

- **Order:** the first `Use` is the outermost stage, as in M.E.AI.
- **The delegate overload** wraps the delegate in an anonymous delegating stage, for one-off around-calls such as an audit record.
- **Unsealed** only so `Minos.NET.DependencyInjection` can derive its registration builder.
- **Extensions**, one static class per stage, each returning `DecisionClientBuilder`:

| Extension | Resolves from `Build(services)` when not given |
|---|---|
| `AsBuilder(this IDecisionClient)` | — |
| `UseOpenTelemetry(this DecisionClientBuilder, string? sourceName = null, Action<OpenTelemetryDecisionClient>? configure = null)` | nothing; the `Minos` source and meter |
| `UseLogging(this DecisionClientBuilder, ILoggerFactory? loggerFactory = null, Action<LoggingDecisionClient>? configure = null)` | `ILoggerFactory`. Without one the stage is skipped, never given a null logger. |
| `UseRetries(this DecisionClientBuilder, Action<DecisionRetryOptions>? configure = null)` | `ILoggerFactory` for event 1003; `TimeProvider`, falling back to `TimeProvider.System` |

### The standard stages

Standard order, outermost first: **telemetry, logging, retries, transport.** This keeps today's events: one span over all attempts, one outcome log inside the span, one retry log per retried attempt.

| Stage | Behaviour |
|---|---|
| `OpenTelemetryDecisionClient` | One CLIENT span and one set of metrics over the whole call, retries included, through the ZeroAlloc.Telemetry proxy generated over an internal operations interface with one `EvaluateAsync(DecisionRequest, …)`. Tags: the request model (`request.Model ?? metadata.DefaultModel`), the question count (`Definition.Questions.Count`), the response model, input and output tokens, cost, each answer's confidence, and `DecisionError.ErrorType` on failure. The provider and `server.*` tags come from `DecisionClientMetadata`, read once in the constructor; without it the provider tag is `"unknown"` and the endpoint tags are left out. With nothing listening it returns the inner task itself. |
| `LoggingDecisionClient` | Logs the outcome once: `EvaluationSucceeded` (1001), `EvaluationFailed` (1002), `UnexpectedException` (1006) through an exception filter that does not catch. With every level it emits disabled it returns the inner task itself. |
| `RetryingDecisionClient` | Takes `DecisionRetryOptions`, an optional `ILogger` and an optional `TimeProvider`. Retries when `ShouldRetry` says so; `RetryAfter` replaces the next delay; exponential backoff, jitter and a cap otherwise. Logs `AttemptRetrying` (1003) for each attempt it retries. Records its own disposal and never starts a retry after it, returning a `Disposed` failure instead. `Disposed` is never retried. |
| `DecisionRetryOptions` | `MaxRetries` (2), `InitialBackoff` (500 ms), `MaxRetryDelay` (30 s), `Jitter` (true), `ShouldRetry` (defaults to `IsTransient`)<br>`static bool IsTransient(DecisionError)`: RateLimited, Overloaded, Server, Network, Timeout, or status 408. It moves here from `IDecisionApi`. |

- **The retry loop** is an internal `DecisionRetry` that `RetryingDecisionClient` and the raw System One calls share. Its delay calculation reuses ZeroAlloc.Resilience's `RetryPolicy` if that exposes one. If it does not, an upstream issue is filed and the calculation is not copied.
- **Allocation rule:** each stage takes a synchronous fast path when the inner call has already completed (`IsCompletedSuccessfully`), with no async state machine, as `WithLogging` and `Evaluated.Unwrap` do today. `RetryingDecisionClient` returns the first call unchanged when it succeeded synchronously or failed with a non-retryable error.

### `DecisionClient`, the facade

- Keeps its six public constructors (options, `HttpClient`, `ILoggerFactory` combinations) and `ConfigureHttpClient`.
- `EvaluateAsync(DecisionRequest)` forwards to a private chain. With `UseStandardPipeline = true`, the default, the chain is OpenTelemetry, then Logging when a logger factory was given, then Retrying, then the internal `DecisionTransport`. With `false`, it is the transport alone.
- `DecisionClientOptions` keeps `MaxRetries`, `InitialBackoff`, `MaxRetryDelay` and `Jitter`, and gains `UseStandardPipeline` (default `true`). The facade copies the retry settings into the `DecisionRetryOptions` of the stage it builds.
- `GetService` returns the facade itself, then `DecisionClientMetadata`, then asks the chain.
- Keeps public `EvaluateAsync(SystemOneRequest, CancellationToken = default)` and `ListModelsAsync(CancellationToken = default)` (see below).
- Throws `ObjectDisposedException` at entry after `Dispose`, as it does today. Disposing it disposes the chain and an owned `HttpClient`.

### `DecisionTransport`, internal

One attempt per call:

1. writes the request through `IDecisionProtocol.WriteRequest` into a pooled buffer;
2. POSTs it to `protocol.EndpointPath` with the `Authorization` header and, when `RetryAttempt > 0`, `X-TypeSafe-Retry-Count`;
3. on success reads the body with `protocol.ReadResponse` into a `DecisionResponse`; on failure maps it through the transport's error mapper;
4. returns every pooled buffer before it completes.

It reports an attempt torn down by disposing an owned `HttpClient` as `Disposed`, and answers an attempt that starts after disposal with `Disposed` without sending it.

### Custom stage example

```csharp
sealed class AuditStage(IDecisionClient inner, IAuditLog log) : DelegatingDecisionClient(inner)
{
    public override async ValueTask<Result<DecisionResponse, DecisionError>> EvaluateAsync(
        DecisionRequest request, CancellationToken cancellationToken = default)
    {
        var result = await base.EvaluateAsync(request, cancellationToken);
        log.Record(request.Definition, result);
        return result;
    }
}
```

## What moves behind the protocol seam

`IDecisionProtocol` grows from questions and answers to the whole System One wire format. `WriteRequest` keeps its current signature; the retry count is a header, which the transport sets.

```csharp
internal interface IDecisionProtocol
{
    string EndpointPath { get; }
    RawJson WriteRequest<TArg>(QuestionSetDefinition definition, TArg state, int stateSizeHint,
                               StateWriter<TArg> writeState, string model, ArrayPool<byte> pool)
        where TArg : allows ref struct;
    Result<DecisionResponse, DecisionError> ReadResponse(ReadOnlySpan<byte> body, QuestionSetDefinition definition);
    DecisionError MapError(int statusCode, ReadOnlySpan<byte> body, TimeSpan? retryAfter);
}
```

| What | From | To |
|---|---|---|
| Endpoint path | `[Post("v1/systemone")]` on `IDecisionApi` | `SystemOneProtocol.EndpointPath` |
| Response envelope: model, usage, id, provider | `TypedEvaluation.ParseResponse`, `ResponseFields` | `SystemOneProtocol.ReadResponse`, one pass over the body |
| Confidences for telemetry | `ConfidenceValues` re-reading the pooled body | `DecisionResponse.Answers[i].Confidence` |
| Error-body interpretation: kind from status and the error JSON, `Detail`, `Failures` | `DecisionErrorMapper` | `SystemOneProtocol.MapError` |
| HTTP-generic errors: network, timeout, disposal, the `Retry-After` header | `DecisionErrorMapper` | The transport's mapper, which calls `protocol.MapError` only when there is a response body |
| Default typed path | `DecisionClient` writing a request, `IDecisionOperations.EvaluateTypedAsync<T>`, `Evaluated<T>` | `DecisionClientExtensions` over `EvaluateAsync(DecisionRequest)`, with `T.Create` reading `response.Slots` |

- **Deleted:** `Evaluated<T>`, `ResponseFields`, `ConfidenceValues`, `AnswerConfidences`; the typed and built-set methods of `IDecisionOperations`; the response-parsing half of `TypedEvaluation` (the state helpers stay); `IDecisionApiResilienceProxy` with the `[Retry]` attribute and `[RetryAttempt]`; `LoggingDecisionApi`; `DisposalGuardDecisionApi`, whose job moves to the retry stage's disposal check and the transport's entry check.
- **The HTTP primitive:** `IDecisionApi` keeps one neutral method that POSTs a `RawJson` to a path and returns a `RawJson`. ZeroAlloc.Rest 3.2.1 has `Body`, `Query`, `Header`, `Get` and `Post` attributes and no path parameter. The plan's first task checks whether its route templates take a runtime path. If they do not, an issue is filed on ZeroAlloc.Rest for a path parameter, and until it ships the transport sends the request with one `HttpClient.SendAsync` over the pooled body, through the same error mapper. That interim is named in the PR and tracked by the upstream issue.
- **The raw System One calls:** `EvaluateAsync(SystemOneRequest)` and `ListModelsAsync` are not `DecisionRequest`-shaped, so they do not run through the stage chain. They keep their span and log through the remaining `IDecisionOperations.EvaluateAsync` and `ListModelsAsync`, and retry through the shared `DecisionRetry` with the same `DecisionRetryOptions`. 6.4 moves them into `Minos.NET.SystemOne`.

## Dependency injection

All six `AddDecisionClient` overloads keep their parameters and return a `DecisionClientServiceBuilder`:

```csharp
public sealed class DecisionClientServiceBuilder : DecisionClientBuilder
{
    public IHttpClientBuilder HttpClient { get; }
    public string? Name { get; }   // null for the default registration
}
```

- **The inner client** is the `DecisionClient` built as today: the factory's named `HttpClient`, the named options, the container's `ILoggerFactory`. With `UseStandardPipeline = true` it carries its standard chain, and stages added with `Use…` wrap it from outside the telemetry span. With `false`, `UseRetries()` takes its defaults from the registration's `DecisionClientOptions`, so configuration-bound retry settings still apply.
- **Registration:** `IDecisionClient` is a singleton built by `builder.Build(provider)`, or a keyed singleton under the name. `TryAdd` semantics stay, so an app's own `IDecisionClient` wins.
- **Repeat calls** for the same name return the same builder instance, held in a keyed marker that replaces `HttpClientConfigured`. Options delegates stack as today, and stages from either call land on one pipeline.
- **Unchanged:** validation and `ValidateOnStart`, the primary handler, the infinite handler lifetime, `RemoveAllLoggers`.

## Tests

- **Stages over a fake inner client:**
  - Telemetry: one span covers every retry; tags come from the neutral types and `DecisionClientMetadata`; missing metadata gives `"unknown"`; with nothing listening the inner task is returned.
  - Logging: 1001, 1002 and 1006; the inner task is returned when every level is disabled.
  - Retries: each retryable kind; `RetryAfter` replacing the backoff; a custom `ShouldRetry`; `RetryAttempt` stamped on the copies; no retry after `Dispose`, which returns `Disposed`; 1003 logged. All on `FakeTimeProvider`, with no real waits.
- **Builder:** `Use` order; the three `Use` overloads; `Build(services)` resolving `ILoggerFactory` and `TimeProvider`; `UseLogging()` skipped without a factory; `GetService<T>` walking the chain; `AsBuilder`.
- **Transport and protocol over a stub handler:** the endpoint path; the retry-count header present only on retries; the envelope read into `DecisionResponse`; `MapError` for each kind; an owned `HttpClient` torn down mid-attempt mapping to `Disposed`; every pooled buffer returned (the counting pool).
- **Facade:** `UseStandardPipeline` true and false; the raw calls still retried, traced and logged; `ObjectDisposedException` after `Dispose`; `GetService` returning the facade and the metadata.
- **`DecisionResponse` public constructor:** a response built from `QuestionAnswer`s feeds `T.Create` and `Answers` and gives the same values as a parsed one.
- **DI:** the return type; `.HttpClient` handlers apply; stages wrap the registered client; a repeat call returns the same builder; keyed registrations; `TryAdd` yields to an app's own client; configuration-bound retry settings reach `UseRetries()` with the standard pipeline off.
- **Existing suites:** the typed, built-set and telemetry tests move to the new path; `ProtocolBoundaryTests` extends to the endpoint path, the envelope field names and the error body; AOT `[Covers]` coverage gains the new public entry points; PublicAPI records the removals.
- **Allocation gates**, only in the published AOT smoke exe, no budget raised:
  - The typed (3328 B) and built-set (3648 B) gates absorb the new `DecisionRequest`, `DecisionResponse` and `AnswerSlot[]`, offset by removing `Evaluated<T>` and the second parse. If a gate breaches, the fix is to cut allocations; if that is impossible, work stops and the measurements go to the maintainer.
  - New gates, each with about 10% headroom rounded up to 64 B per the Phase 1.8 rule: `EvaluateAsync(DecisionRequest)` on the standard pipeline, idle and listening; the bare transport; a `DelegatingDecisionClient` pass-through over a synchronous inner call at 0 B.
- **Live smoke:** the existing live suite runs unchanged through the extension methods.

## Open Questions

- Whether ZeroAlloc.Rest route templates accept a runtime path (Task 1 of the plan answers it; see the HTTP primitive above).
- Whether ZeroAlloc.Resilience exposes its delay calculation for reuse (answered while building `DecisionRetry`; an upstream issue if not).

## Risks

- **Allocation budgets:** the neutral response adds objects to the typed path. Mitigated by the struct answer view, deleting `Evaluated<T>` and the second parse, and measuring in the published exe before each commit that touches the path.
- **Telemetry parity:** moving the span from three generated methods to one stage could drop or rename a tag. Mitigated by keeping the existing tag and metric tests and running them against the stage.
- **Retry semantics:** moving retries from the generated resilience proxy to a hand-written loop could change timing or disposal behaviour. Mitigated by porting the existing retry and disposal tests unchanged before replacing the proxy.
- **Breaking surface:** every consumer that implements `IDecisionClient` or uses `AddDecisionClient`'s return value breaks. Mitigated by the migration table, the docs page and the `feat!` changelog entry.
